## Notes for later milestones

- **M8 (auth rate limiting behind a proxy):** Better Auth keys rate limits by client IP from `x-forwarded-for` and does not trust comma-separated chains by default. Behind the host's proxy, set `advanced.ipAddress.ipAddressHeaders` / `trustedProxies` to the host's documented header, or all clients may share one bucket.
- **M8 (breached-password check):** the Have I Been Pwned check fails closed. If the API is unreachable, sign-up and password changes are refused rather than skipping the check. Monitor for `PASSWORD_COMPROMISED`/upstream errors after deployment.
- **M8 (tracking links in access logs):** the app never logs `/t/{token}` paths, but the hosting platform's request logs and any CDN may record full URLs. Check the provider's log settings; redact or disable path logging for `/t/` and `/api/v1/portal/t/` where possible, and document the log retention (ADR-0012).
- **M8:** Next.js generates per-build keys (preview mode, server actions) inside `.next/`. Gitleaks flags them in a local directory scan. They are gitignored, and the git-history scan in CI is clean. If multiple instances are deployed, set `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY` consistently (check current Next.js docs at M8).
