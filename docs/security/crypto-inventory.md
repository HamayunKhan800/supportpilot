# Cryptographic inventory and key management

> M7 step 5 (finding M7-13, ASVS V11.1.1 and V11.1.2) · 2026-10-25. Every entry was checked in the app's source or in the library source under `node_modules` (better-auth 1.7.12). There is no hand-written cryptography: the app uses Node's `node:crypto` and the library's functions.

## Algorithms in use

| What                                       | Algorithm and settings                                                                                                                                                                                           | Where                                                                                |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Passwords                                  | scrypt, N=2^14, r=8, p=5 (an OWASP Password Storage Cheat Sheet setting, 16 MiB per hash), 16-byte random salt, 32-byte key, NFKC-normalised input, constant-time compare. Format `$scrypt$n=…,r=…,p=…$salt$key` | `src/server/platform/auth/password.ts` (M7-02)                                       |
| Passwords from before M7                   | Library scrypt (N=2^14, r=16, p=1). Still accepted; replaced with the format above at the next correct sign-in                                                                                                   | `better-auth/crypto` `verifyPassword`; upgrade in `auth.ts` after-hook               |
| Session tokens                             | 32 random characters from the library's generator (`generateId(32)`), stored server-side                                                                                                                         | better-auth `db/internal-adapter`                                                    |
| Session cookie                             | `<token>.<signature>`, signed with HMAC-SHA256 using `BETTER_AUTH_SECRET`. A bare token is refused (tested)                                                                                                      | better-auth `crypto`; `tests/integration/auth.test.ts`                               |
| Google and GitHub tokens                   | XChaCha20-Poly1305 (`@noble/ciphers`), key = SHA-256 of the secret, random nonce per value (`encryptOAuthTokens`, M7-07)                                                                                         | better-auth `crypto` `symmetricEncrypt`                                              |
| Password-reset and other verification keys | Stored as SHA-256 (base64url) of the identifier (`verification.storeIdentifier: "hashed"`)                                                                                                                       | better-auth `db/verification-token-storage`                                          |
| Email verification codes                   | 6 digits, stored as SHA-256 (base64url), compared in constant time (`storeOTP: "hashed"`)                                                                                                                        | better-auth `plugins/email-otp`                                                      |
| Customer tracking links                    | 32 random bytes (256 bits) from `randomBytes`; only the SHA-256 is stored                                                                                                                                        | `src/server/modules/tickets/tracking-token.ts` (ADR-0012)                            |
| Rate-limit keys                            | HMAC-SHA256 of the IP or email with `BETTER_AUTH_SECRET`, truncated to 32 base64url characters, so the table holds no raw addresses                                                                              | `src/server/platform/rate-limit.ts`                                                  |
| Content hashes (evaluation review)         | SHA-256, integrity only (detects a changed test case)                                                                                                                                                            | `scripts/lib/eval-runner.ts`                                                         |
| Transport                                  | TLS, terminated by the hosting platform                                                                                                                                                                          | Checked at deployment (M8). Locally the app runs over plain HTTP on `127.0.0.1` only |

Not used: JWTs for sessions, client-side cryptography, MD5 or SHA-1 for anything security-related.

## Secrets

| Secret                                         | Used for                                                   | Kept in                                    | If it leaks or is rotated                                                                                                                                                                                                                     |
| ---------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BETTER_AUTH_SECRET` (at least 32 characters)  | Cookie signatures, OAuth-token encryption, rate-limit HMAC | Host environment variable; never committed | Changing it signs everyone out and makes stored OAuth tokens unreadable (they are refreshed at the next provider sign-in). Better Auth 1.7 also supports versioned keys (`BETTER_AUTH_SECRETS`) for rotation without that; to be set up at M8 |
| `GEMINI_API_KEY`                               | AI drafts, triage and embeddings                           | Host environment variable                  | Revoke in Google AI Studio and replace                                                                                                                                                                                                        |
| `GOOGLE_CLIENT_SECRET`, `GITHUB_CLIENT_SECRET` | Provider sign-in                                           | Host environment variable                  | Rotate in the provider's console                                                                                                                                                                                                              |
| `RESEND_API_KEY`                               | Account emails (M8)                                        | Host environment variable                  | Revoke in Resend and replace                                                                                                                                                                                                                  |
| Database URL                                   | PostgreSQL                                                 | Host environment variable                  | Rotate the database password                                                                                                                                                                                                                  |

`src/server/platform/env.ts` validates every setting at start-up and refuses to run with a missing or short secret. gitleaks runs on every push and on the full history (`.github/workflows/security.yml`). `.env.example` holds placeholders only.

## When to revisit

- **New parameters:** when OWASP raises its scrypt guidance or the server gets more memory, change `PASSWORD_HASH_PARAMS`. Old hashes keep working and are upgraded at sign-in.
- **Library upgrades:** re-check this table when better-auth changes major or minor version.
- **Post-quantum:** nothing here depends on public-key cryptography the app controls (TLS is the platform's). No action for v1.
