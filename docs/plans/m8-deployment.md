## Revision 2: AWS Lambda (approved 2026-10-27)

### Why the change

Google Cloud needs a payment card it accepts, even for the free trial. The owner's SadaPay virtual card was refused, matching Google's rule against virtual and prepaid cards ([Google help](https://support.google.com/cloud/answer/7350297?hl=en)), and no other card is available now. AWS's new sign-up asks most new customers for no payment method ([AWS](https://aws.amazon.com/resources/create-account/)); the owner's account was created that way on 2026-10-27: **Free plan, $100 credit, ends 27 April 2027**. The Free plan can't be charged; when it ends, the account closes unless upgraded (upgrading most likely needs a card) ([AWS Free Tier](https://aws.amazon.com/free/)).

**Why Lambda and not EC2, Fargate or Lightsail:** the demo is used now and then, not around the clock.

- Lambda charges only while code runs, and the always-free allowance (1 million requests and 400,000 GB-seconds a month) covers that ([pricing](https://aws.amazon.com/lambda/pricing/)). It is also the most-used AWS compute service: 65% of AWS customers ([Datadog 2025](https://www.datadoghq.com/state-of-containers-and-serverless/)).
- **EC2** (`t4g.micro`) is always on: about $13 a month in Sydney, paid whether or not anyone visits.
- **ECS Fargate** with a load balancer is the usual setup for always-on containers, but costs about $50 a month in Sydney (about 2 months of the credit).
- **Lightsail** costs $15 a month ([pricing](https://aws.amazon.com/lightsail/pricing/)).

### Revised code changes (each with tests)

1. **Dockerfile:** add the Lambda Web Adapter (pinned by digest). It only runs inside Lambda; `docker run` elsewhere is unchanged.
2. **Launcher modes:** `web` (load SSM secrets, start Next.js only) and `jobs` (load secrets, then serve the adapter's event path: `drain`, `migrate`, `seed-reset`). The existing web + worker mode stays for container platforms.
3. **Wake the worker:** after queuing a job, the web app invokes the worker function asynchronously when `WORKER_FUNCTION_NAME` is set (a no-op otherwise, so local and CI behave as today).
4. **One address:** the production redirect also covers the `*.lambda-url.*.on.aws` address. **Moved to step 6 (domain)**: until a domain exists the Function URL _is_ the app's address, so there is nothing to redirect. Behind CloudFront the request reaches the function with the Function URL as its host, so a plain host check would redirect every visitor in a loop. Step 6 designs it with CloudFront: forward the visitor's host (`X-Forwarded-Host`, also needed by Next.js's Server Actions origin check) plus a secret origin header, and redirect only direct visits that lack it.
5. **Lambda limits, checked by test:** the request body limit is 6 MB including encoding, so the 5 MB upload limit is measured and lowered to 4 MB if needed. The read-only file system is handled (only `/tmp` is writable).
6. **New runtime dependencies:** `@aws-sdk/client-ssm` and `@aws-sdk/client-lambda` (official AWS SDK), loaded only when the AWS settings are present.

# Original plan (approved 2026-10-25, superseded where Revision 2 differs)

## Goal

A live, always-reachable demo on the owner's domain, deployed by GitHub Actions from `main`, with a staging copy checked before every production release, and the M8 items left over from earlier milestones closed or written down.

**Exit criteria (all verified, not assumed):**

1. `https://<domain>` serves the app over HTTPS with a public certificate; the demo accounts sign in; the portal accepts a request; Gemini triages it and drafts a cited reply.
2. A push to `main` builds one image, deploys it to staging, migrates, smoke-tests, then waits for the owner's approval before production. A bad release can be rolled back to the previous revision in one command, and that has been tried once.
3. No long-lived cloud keys anywhere: GitHub signs in to Google with Workload Identity Federation; app secrets live in Secret Manager.
4. A budget alert and a spend cap exist, and the expected monthly cost is shown against the real bill after one week.
5. Real email (password reset, verification code) works from the domain, with SPF, DKIM and DMARC passing.
6. The 10 ASVS items marked "M8" and the M8 notes in `accepted-risks.md` are each checked on the live site and given a verdict.

## Code changes (small; each with tests)

1. **Container launcher** (`scripts/start-container.mjs`, copied into the image): starts `server.js` and `.build/worker.mjs`, passes `SIGTERM` to both, and exits if either stops so Cloud Run restarts the instance. The default `CMD` for other platforms stays `node server.js`.
2. **Demo safety.** Visitors share the demo accounts, so:
   - the demo accounts can't change their password, name or email, or remove members (refused on the server, with a clear message);
   - no email is ever sent to a demo address, and the demo addresses move to the owner's domain (today they use `demo.supportpilot.dev`, a domain we don't own: a reset email there could reach a stranger once email is live);
   - a scheduled GitHub Action resets the demo workspace once a day (runs `seed-demo` as a Cloud Run job, bundled into the image with a new `--reset` mode).
3. **One address only:** in production, requests to the `*.run.app` address redirect to `<domain>` (the run.app URL can't be switched off while domain mapping is used).
4. **Daily embedding cap for the demo** (M4 note): search and upload embeddings get a daily limit, like generation already has.
5. **TRACE** (M7-11): checked on the live site first. Google's front end may already refuse it; if not, the launcher answers 405 before Next.js.

No table changes. No new runtime dependencies.

## Risks and limits (honest list)

- **First visit after a quiet spell is slower** (the app and the database wake up). Measured in step 6; if it is more than a few seconds, the options are one warm instance in working hours (a small cost) or accepting it.
- **Domain mapping is Preview** (AR-009). If it misbehaves, the fix is the load balancer (about $18 a month), with your approval.
- **Free plans change.** Every limit above is re-checked on the official pages before step 3, and the week-1 bill is compared with this plan.
- **Shared demo accounts** can still be used to make a mess between daily resets; anything harmful is blocked, the rest is reset.
- **The daily reset spends AI quota:** it re-embeds 153 help-article chunks and re-triages 25 tickets (measured 2026-10-25), so 153 of the 800 daily embeddings and 25 of the 200 daily generation calls. It runs just after Google's daily quota reset (midnight Pacific time: 12:00 PKT in summer time, 13:00 PKT in winter) so visitors get the rest.
- **Gemini free tier**: Google may use inputs to improve its products, so the demo stays on synthetic data, and the sign-up page says so.
