# M5 · AI features: implementation plan

> Status: **Approved 2026-10-22** · Drafted 2026-10-22
> Implements FR-AI1–AI8 (docs/01 §3), the AI parts of US-1–US-4, NFR-AI2, and threats T7, T8, T9, T10, T13, T16, T17 (docs/03).
> Roadmap row (docs/00): "Triage (structured output), streamed RAG drafts with citations, approve/edit/send, failure handling, budgets". Done when: unit tests with a mocked LLM, a fault-injection test and an injection test set pass.
> Builds on M4's retrieval. Everything is built and tested with the **mock** provider first; Gemini is used only for a small, budgeted smoke run at the end (step 6).

## 1. What a user can do when M5 is done

**Customer** (portal, unchanged): submits a ticket. Within seconds, and without waiting, the ticket is **triaged** in the background.

**Agent** (signed in), on a ticket page:

1. Sees the **AI triage**: category, priority, sentiment, language, confidence and a one-line reason. High-confidence labels are applied automatically; low-confidence ones show **"Needs review"** with one-click accept. Changing a label records an **override** for evaluation (FR-AI1, FR-AI2).
2. Clicks **Generate draft**. Text starts **streaming** within a few seconds, with citations like `[1] [2]`. Each citation opens the exact source passage, or shows **"source removed"** if the document was deleted since (FR-AI3, FR-K3).
3. If the knowledge base has nothing relevant, sees **"Insufficient knowledge: no reliable sources found"** instantly, and **no AI call is made** (FR-AI4, US-3).
4. **Edits** the draft and clicks **Approve & send**, which posts it as their own reply. Nothing AI-written reaches a customer without this click (FR-AI5, ADR-0009).
5. Gives 👍/👎 with a reason (FR-AI6).
6. If the AI is down, slow or over budget, sees a clear, retryable message. Everything else (reading, replying, notes) keeps working (FR-AI7, FR-AI8, US-4).

**Admin / owner**, on a new **AI settings** page: turns AI on/off, sets the monthly token budget and the triage confidence threshold, edits the category list, and sees this month's usage and estimated cost.

## 2. Design decisions

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Why                                                                                                                                                                                                                                                                                                                                   |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | **Models:** triage with **`gemini-3.5-flash-lite`**, drafts with **`gemini-3.8-flash`**. Both are stable, on the free tier, and support structured output; neither has a shutdown date ([deprecations](https://ai.google.dev/gemini-api/docs/deprecations), checked 2026-10-22). Model ids live in one config file and are stored on every result row. `gemini-3.1-flash-lite` is avoided (shuts down 2027-05-07).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Cheapest model for a simple classification; a stronger one for writing. Paid-tier list prices (for cost reporting): Flash-Lite $0.30 / $2.50 and Flash $0.75 / $3.75 per 1M input / output tokens, Flash doubling on 2027-01-01 ([pricing](https://ai.google.dev/gemini-api/docs/pricing)). The price table is dated, as in ADR-0006. |
| D2  | **Thinking set low.** Drafts use `thinkingLevel: "low"` (`minimal` returns an error on 3.8 Flash, per its model page); triage uses the lowest level the model accepts, verified in step 1. Thinking tokens are billed as output.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Latency and cost; these tasks don't need long reasoning.                                                                                                                                                                                                                                                                              |
| D3  | **One AI module** (`src/server/modules/ai/`) behind an interface with two providers: **`gemini`** (AI SDK `generateText` with `Output.object` for triage, `streamText` for drafts) and **`mock`** (deterministic: keyword-based triage; drafts built from the retrieved passages with valid citations). Fault cases are tested with the SDK's **`MockLanguageModelV4`** (`ai/test`). **No new dependencies.**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Same pattern as M4's embedder. CI stays free and repeatable.                                                                                                                                                                                                                                                                          |
| D4  | **Triage runs as a background job** (`ai.triage`, pg-boss, with a dead-letter queue), enqueued **in the same transaction** that creates the ticket, from both the portal and the agent UI. The output is validated with Zod: category must be one of the workspace's categories, plus priority, sentiment, language (ISO 639-1), confidence 0–1 and a reason of at most 200 characters. Invalid output is retried once, then recorded as failed. **Changed in step 2 (2026-10-22):** (a) Gemini ignores string length limits and has no regex `pattern` (finding #78), so the schema keeps only what Gemini enforces (category, priority and sentiment as enums, confidence 0–1); the app then cleans up: the reason is shortened to 200 characters, and a language that isn't a two-letter code becomes "unknown" instead of failing the run. (b) A new `flags` column (migration 0005) records hidden characters removed from the customer's text; a flagged run never changes the ticket, it only suggests. (c) Invalid output is retried once straight away; temporary provider errors go back to pg-boss (3 retries, back-off from 30 s), then the run is recorded as failed. AI switched off, budget used up or daily cap reached record a "skipped" run without retrying. | Portal submission stays fast (US-1). Structured output plus schema validation (OWASP LLM10:2026, Improper Output Handling).                                                                                                                                                                                                           |
| D5  | **Triage never overwrites a human.** Labels are applied only if confidence ≥ the workspace threshold (default 0.7) **and** no agent has set that field. Otherwise they are shown as a suggestion with "Needs review" (inbox filter). Every agent change after triage is stored as an override (old value, new value, AI confidence).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | FR-AI2. Overrides become evaluation data (docs/04 §5).                                                                                                                                                                                                                                                                                |
| D6  | **Drafts stream directly from the web server** (not a job), from `POST /api/v1/tickets/{id}/drafts`, as newline-delimited JSON events: `start` (draft id), `delta`, then `done` (validated citations, warnings) or `error` (code, retryable). _Built with the ticket's UUID `{id}`, not `{number}`, like every other ticket route in /api/v1 (step 3)._ Headers `Content-Encoding: none` (AI SDK guidance for proxies) and `Cache-Control: no-store`. The client reads it with `fetch`, which fits our strict CSP (`connect-src 'self'`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Interactive. Our own small protocol is easier to test than a chat UI library, and we don't need chat.                                                                                                                                                                                                                                 |
| D7  | **Refuse before calling the LLM** (FR-AI4). The retrieval query is the ticket subject plus the latest customer message. If search returns nothing, or the best vector match is below the workspace's `retrieval_min_score`, the result is "insufficient knowledge" with **no LLM call**. The starting threshold comes from the Gemini score distributions of the 110 answerable vs 30 unanswerable questions (M4 step 6); M6 calibrates it properly. The model may also answer with a fixed `INSUFFICIENT_KNOWLEDGE` marker when the passages don't contain the answer, which is treated as a refusal. **Changed after the Gemini run (2026-10-22, finding #87):** scores of answerable and unanswerable questions overlap (0.638–0.890 vs 0.570–0.800), so no cut-off meets the targets. `retrieval_min_score` starts at **0.65** (step 3 changes the column default from M2's placeholder 0.5 in a migration) as a safety net for clearly off-topic tickets (1 of 110 answerable questions wrongly refused). The `INSUFFICIENT_KNOWLEDGE` answer is the main refusal mechanism, and step 6 and M6 must measure it.                                                                                                                                                             | Cheaper and safer: no guessing when the knowledge base is silent (OWASP LLM07:2026, Misinformation).                                                                                                                                                                                                                                  |
| D8  | **Citations are checked by code, not trusted.** The model sees passages numbered `[1]`–`[5]`. After streaming, markers outside the retrieved set are **removed and counted** (target: 100% valid, docs/04). Each citation is saved as a **snapshot** (document title, heading, passage text, chunk id), so it still opens after the document is deleted, labelled "source removed".                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Deterministic citation validity. FR-K3.                                                                                                                                                                                                                                                                                               |
| D9  | **Drafts are plain text.** No Markdown or HTML is rendered; links are not made clickable; citation markers become buttons. Before sending, `[n]` markers are removed from the customer's copy (the agent sees a preview of exactly what the customer receives).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Closes T10 (data theft through a rendered image or link) by design rather than by sanitising. Customers can't open internal passages, so markers would only confuse them.                                                                                                                                                             |
| D10 | **Prompt-injection defences, by limiting impact** (OWASP LLM01:2026 and the [OWASP prompt-injection cheat sheet](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html), which says input filtering and prompt wording are **not** security boundaries): (a) no tools, no write access, human approval (ADR-0009, LLM03:2026 Excessive Agency); (b) trusted instructions in the system prompt, ticket and passages in clearly labelled data blocks; (c) a **canary** string in the system prompt: a draft containing it is blocked and logged; (d) drafts with **links or email addresses not found in the sources or ticket** get a visible warning for the agent; (e) **invisible Unicode tag characters** (U+E0000–E007F) are removed from the prompt copy and the ticket is flagged.                                                                                                                                                                                                                                                                                                                                                                                                                                               | Prompt injection can't be fully prevented, so the plan makes a successful one harmless and visible.                                                                                                                                                                                                                                   |
| D11 | **What the model sees, and what it doesn't.** Included: subject, customer messages and agents' public replies (last 6 messages, at most 8,000 characters), and the top 5 passages. **Excluded: internal notes** (they could leak into a customer reply), customer email address and name. Prompt text is never logged; logs carry ids, sizes, timings and token counts.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Data minimisation (LLM02:2026, T13, T17).                                                                                                                                                                                                                                                                                             |
| D12 | **Cost and abuse limits** (LLM06:2026, Unbounded Consumption): (a) the per-workspace **monthly token budget** (existing column, default 1M) is checked before every call; when exhausted, drafting shows a clear message and triage is skipped (FR-AI7); (b) a **global daily cap on AI calls** (`AI_DAILY_CALL_LIMIT`), across all workspaces, so the public demo can't use up the free-tier quota (finding #70); (c) rate limits per user and per workspace for drafts; (d) caps on input size and output tokens (triage 200, drafts 800); (e) timeouts: triage 20 s total; drafts 15 s to the first word, 10 s between words, 60 s total (AI SDK `timeout` options).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Free-tier quotas are per project and per model and aren't published as a fixed table, so the app protects itself.                                                                                                                                                                                                                     |
| D13 | **Failure handling** (FR-AI8, T16): temporary errors (429/5xx) are retried for triage by the job queue with back-off, not by the SDK (changed in step 1: SDK retries are off so that the daily cap counts every provider request, ADR-0015); drafts make one attempt (the agent can retry). A **circuit breaker** stops calling the provider for 60 s after 5 consecutive failures and answers "AI temporarily unavailable" at once. A client disconnect aborts the model call. Every outcome (ok, refused, blocked, timeout, error, aborted) is recorded.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Fail fast; non-AI features unaffected. Fault-injection tests cover each path.                                                                                                                                                                                                                                                         |
| D14 | **Measured, not assumed** (NFR-AI2): every call records model, prompt version, input/output tokens, latency, time to first token (drafts) and estimated cost in `ai_usage`. Prompts live in versioned files (`triage.v1`, `draft.v1`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Evaluation and the M6 dashboard depend on it.                                                                                                                                                                                                                                                                                         |
| D15 | **Drafts answer in the customer's language** (from triage); the knowledge base stays English.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | docs/01: customer messages in any language are supported.                                                                                                                                                                                                                                                                             |

**Rough cost per call** (estimates for the paid tier; the free tier costs $0): a draft is about 3,000 input and 600 output tokens, so about **$0.005**; a triage call about 600 and 100, about **$0.0004**. Step 6 measures the real numbers.

## 3. Steps (each one committed with CI green)

1. **Foundations:**
   - Threat model remapped to the **OWASP LLM Top 10 2026** (published 2026-08-04; [official repository](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10)), which replaced the 2025 list our docs cite. ADR-0015 (ADR-0014 is reserved for the M4 search-fusion decision) (models, thinking, prompt versioning, streaming protocol).
   - Migration `0004`: `ticket_triage` (one row per run, plus applied/override fields), `ai_draft`, `ai_draft_citation` (snapshots), new `ai_usage` columns (outcome, latency, time to first token, ticket id).
   - The AI module: interface, mock and Gemini providers, budget check, daily cap, circuit breaker, timeouts, usage recording.
   - Unit tests, including fault injection with `MockLanguageModelV4`: 429, 500, timeout, stalled stream, malformed JSON, schema-invalid output, abort.
2. **Triage:** prompt v1 and schema; the `ai.triage` job and dead-letter queue; enqueue in both ticket-creation paths; D5 rules; override recording; triage card and "Needs review" filter in the UI. Integration, mutation and E2E tests.
3. **Draft engine:** retrieval → refusal gate → prompt v1 → stream → citation validation → canary/link checks → save; the streaming REST endpoint in OpenAPI; rate limits. Integration tests with the mock provider and every fault path.
4. **Draft UI:** draft panel with streaming text (screen readers hear "Draft ready", not every word), citation buttons with passage view and "source removed", edit, customer preview, **Approve & send**, discard, 👍/👎. E2E on desktop and mobile, plus axe accessibility checks.
5. **AI settings page** (admin+): AI on/off, budget and this month's usage, threshold, categories. E2E covering budget exhaustion.
6. **Evaluation and security:**
   - **Injection test set (~20 cases):** 12 direct (in tickets) and 8 indirect (in knowledge-base passages, including the poisoned article kept since M4). Run in CI with the mock provider to check the pipeline defences: canary blocking, link warnings, hidden characters, no internal notes in prompts.
   - **One budgeted Gemini smoke run** (about 60 calls, well under the free daily limits): ~20 triage tickets, ~20 drafts (answerable and unanswerable) and the 20 injection cases. Measures latency, time to first token, tokens, cost, refusals and injection results.
   - Docs, screenshots, README, milestones.

## 4. Done when

- [ ] FR-AI1–AI8 work end to end with the mock provider (E2E on desktop and mobile).
- [ ] Unit tests with a mocked LLM and fault-injection tests pass (every failure path in D13).
- [ ] The injection test set exists, runs in CI with the mock, and has been run once against Gemini, with results recorded (failures documented, not hidden).
- [ ] Citation validity is checked by code; invalid markers are removed and counted.
- [ ] No AI call is made for "insufficient knowledge" (tested).
- [ ] Budget, daily cap, rate limits and circuit breaker are tested.
- [ ] Gemini smoke-run results (latency, time to first token, tokens, cost) are recorded in `docs/eval/`.
- [x] Threat model updated to the OWASP LLM Top 10 2026 (step 1).
- [ ] CI green.

## 5. Out of scope for M5

- **Accuracy evaluation:** the ~150-ticket triage golden set, groundedness judging and threshold calibration (M6).
- **Analytics dashboard** (FR-AN1, M6).
- **Email notifications** (M8). **Autonomous replies** (never in v1, ADR-0009). **PII redaction** (stretch goal).
- **Chat with the AI** or multi-turn drafting. One draft per click; regenerate to try again.
