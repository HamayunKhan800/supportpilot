# 03 · Threat Model

> Milestone M0 · **Re-reviewed at M7 step 1 (2026-10-25)** against the code as built: §3a lists every entry point, §4 adds T20–T27, and §4a says how each threat is checked in M7.
> References: [OWASP Top 10:2025](https://owasp.org/Top10/2025/) · [OWASP Top 10 for LLM Applications 2026](https://github.com/GenAI-Security-Project/GenAI-LLM-Top10) (published 2026-08-04; replaced the 2025 edition this document first used, remapped at M5 step 1) · [OWASP LLM Prompt Injection Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html) · OWASP ASVS (used as checklist at M7).

## 1. Assets

| Asset                                        | Why it matters                                        |
| -------------------------------------------- | ----------------------------------------------------- |
| Tenant data: tickets, messages, KB documents | Confidentiality between companies is the core promise |
| Credentials & sessions                       | Account takeover                                      |
| Tracking tokens                              | Grant access to one customer's ticket                 |
| AI provider API key & token budget           | Direct financial loss / service denial                |
| Audit log                                    | Accountability, incident investigation                |
| CI/CD pipeline & deploy credentials          | Supply-chain compromise                               |

## 2. Threat actors

1. **Anonymous internet user**: portal spam, prompt injection via ticket text, token guessing, DoS/cost abuse.
2. **Authenticated user of another tenant**: IDOR / cross-tenant access.
3. **Low-privilege member (agent)**: privilege escalation to admin actions.
4. **Malicious or careless KB uploader**: poisoned documents (indirect prompt injection), malformed files.
5. **Supply-chain attacker**: compromised npm package or GitHub Action.

## 3. Trust boundaries

Browser ↔ web app · web/worker ↔ Postgres · web/worker ↔ LLM provider (data leaves our system) · GitHub Actions ↔ hosting platform · **LLM output ↔ our UI** (model output is untrusted input).

## 3a. Attack surface (M7 inventory)

Every way into the app, read from the route files and the auth configuration on 2026-10-25.

| Entry point                                                        | Who can call it             | Guard                                                                                                                                                                                                                         |
| ------------------------------------------------------------------ | --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Pages under `/app/*`                                               | Signed-in members           | `requireAppWorkspace()` on every page; role checks per page (`can()`); `/app/review` is a 404 for anyone not on the reviewer list                                                                                             |
| `/api/v1/tickets…`, `/drafts…`, `/kb…`, `/settings/ai` (13 routes) | Signed-in members           | `apiRoute()`: session, workspace and permission checked in the service; zod body; Origin check on writes; RFC 9457 errors                                                                                                     |
| `/api/v1/portal/{slug}/tickets`                                    | Anyone                      | Per-IP and per-workspace rate limits, honeypot, zod, size limits                                                                                                                                                              |
| `/api/v1/portal/t/{token}…`                                        | Anyone with a tracking link | 256-bit token, stored hashed; `no-store`, `no-referrer`                                                                                                                                                                       |
| `/api/v1/openapi.json`                                             | Anyone                      | Public by design (describes the API, holds no data)                                                                                                                                                                           |
| `/api/auth/*` (Better Auth)                                        | Anyone / signed-in users    | Library endpoints, including ones the UI never calls (organization update and leave, user update, sessions, accounts). Unused email endpoints closed (`disabledPaths`); library rate limits; Origin and CSRF checks forced on |
| `/api/internal/review/…`                                           | Reviewers only              | 404 unless the reviewer feature is on and the user is listed                                                                                                                                                                  |
| `/api/dev/email-outbox`                                            | Tests only                  | 404 unless `EMAIL_PROVIDER=outbox` and the request carries `EMAIL_OUTBOX_TOKEN`                                                                                                                                               |
| `/api/health`, `/api/ready`                                        | Anyone                      | No data; `ready` shows only database status and latency                                                                                                                                                                       |
| Background worker (pg-boss jobs)                                   | Internal                    | Jobs carry IDs only; each job re-reads data scoped to its workspace                                                                                                                                                           |
| GitHub Actions (CI, Security, Gemini eval)                         | Repository owner            | Actions pinned by SHA; the Gemini key only in a protected environment on a manual workflow                                                                                                                                    |

| T12 | **D/T**: Malicious file (zip bomb, giant PDF, wrong type)                                                                                                                                                                                                                        | Size limit, magic-byte check, page cap, parse in worker with timeout & memory limit                                                                                                                                                                             | Fixture tests                                                                                                                          |

| T15 | **R**: Member denies destructive action                                                                                                                                                                                                                                          | Append-only audit log for role changes, deletes, approvals, settings                                                                                                                                                                                            | Test: actions create audit rows                                                                                                        |
| T16 | **D**: Provider outage / slowness                                                                                                                                                                                                                                                | Timeouts, circuit breaker, graceful degradation                                                                                                                                                                                                                 | Fault-injection test                                                                                                                   |
| T18 | **S**: Account takeover through password reset or email verification (guessed or leaked token, account enumeration, flooding)                                                                                                                                                    | Single-use 30-minute reset links and 10-minute codes with 3 tries, both stored hashed; same answers and timing for unknown emails; `no-referrer` on reset paths; sessions revoked on reset; change notice by email; per-IP rate limits (per-account limits: M7) | Integration + E2E (`auth-email.test.ts`, `accounts.spec.ts`)                                                                           |
| T19 | **S**: Pre-account takeover through Google/GitHub linking (attacker registers the victim's email first)                                                                                                                                                                          | Linking only when the provider and this app have both verified the email (`requireLocalEmailVerified`); no `trustedProviders`; only `openid email profile` from Google                                                                                          | Integration test of the authorization URL; library code checked (ADR-0020)                                                             |
| T17 | **I**: Customer PII sent to third-party LLM                                                                                                                                                                                                                                      | Synthetic demo data only; portal notice; PII redaction planned as stretch                                                                                                                                                                                       | Documented limitation                                                                                                                  |
| T20 | **D**: One user creates many workspaces; each gets its own monthly AI budget, so the budgets add up, and the database fills                                                                                                                                                      | Global daily AI call cap (`AI_DAILY_CALL_LIMIT`) bounds the real cost. | T22 | **S**: With email off, someone registers the invitee's email without proving it, then opens a leaked invitation link                                                                                                                                                             | Invitation IDs are random and only shown to the admin who created them; with email on, sign-in needs a verified email                                                                                                                                           | M7 step 4: check `requireEmailVerificationOnInvitation` and the accept flow                                                            |
| T23 | **I**: Test-only endpoints left reachable in production                                                                                                                                                                                                                          | Outbox and review routes answer 404 unless explicitly switched on (§3a)                                                                                                                                                                                         | Existing tests; re-checked against a production build in step 4                                                                        |
| T24 | **I/E**: Abuse of CI to read the Gemini key or push code                                                                                                                                                                                                                         | Key only in a protected environment, manual workflow; pull requests from forks get no secrets; least-privilege `permissions:`                                                                                                                                   | M7 step 2 (CI config review)                                                                                                           |

| T26 | **S/I**: Open redirect through `callbackURL`, `next` or OAuth error redirects                                                                                                                                                                                                    | `safeRedirect()` for app redirects; the library checks callback URLs against trusted origins                                                                                                                                                                    | M7 step 4: try external and `//host` targets                                                                                           |

A faked single value gets a fresh limit per request (password guessing); with no usable IP, everyone shares one bucket (one attacker can block sign-in for all) | The app's own limiter (portal) already uses `TRUST_PROXY_HEADERS`; the auth library is not wired to it                                                                                                                                                          | **Found by code review in step 1** (better-auth 1.7.12 `getIP`, rate limiter `no-trusted-ip` bucket). Confirm in step 4, fix in step 5 |

### 4a. How each threat is checked in M7

- **Step 4 (tests against a production build):** T1 and T2 as a full matrix (every `/api/v1` route with another workspace's IDs must answer 404; an agent on admin actions must get 403), T3, T5, T6, T7, T12, T18, T20–T23, T26, T27.
- **Step 2 (ASVS checklist, by reading code and config):** T4 (cookie flags), T10, T11, T13, T14, T15, T16, T24.
- **Already measured (M5, M6):** T8, T9 (injection eval set, 100% resisted), T25 (privacy tests), T17 (documented limitation).

| Category                                   | Primary controls                                                                                                                                                                                                |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A01 Broken Access Control                  | T1, T2, T6, T21, T23; deny by default; tenant-scoped repositories                                                                                                                                               |

## 7. Accepted risks (v1)

- Prompt injection cannot be fully prevented by any known technique. We limit the **impact** (no tools, human approval) rather than claim prevention.
- The free-tier AI provider may use submitted data to improve its products, so only synthetic data is used.
- A single region with no multi-region failover.
