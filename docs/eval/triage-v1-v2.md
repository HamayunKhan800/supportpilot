# Triage prompt v1 vs v2 (M6 step 6, decision D6a)

**Result: the app now uses triage prompt v2.** It was more accurate on priority by a margin that
passed the decision rule, and it was not worse on anything. Category accuracy also went up, but
that gain alone did not pass the rule's bar.

Both runs used the same 150 labelled tickets, the same model (`gemini-3.5-flash-lite`, Gemini
free tier) and the same scoring code. Only the prompt changed. v2 was written and frozen (commit
`ee49e4a`, SHA-256 `0a94b6e96fdc507c830a2368a19195f9bf687148033d5807871cd78f2f962e28`)
before it was measured, and the decision rule below was fixed before either run.

## Comparison (generated by `pnpm eval:compare`)

Runs: v1 `d4f53fa4-2080-4fc1-babd-8ee4f1acbcd6` (completed), v2 `75a705fc-19bf-4ef5-921b-5ce6db7e0068` (stopped).
Provider gemini, triage model `gemini-3.5-flash-lite`, same dataset (`ba1b4b3d915f`).
Paired tickets (answered by both): 150 (v1 answered 150, v2 150).

| Metric          | v1 (95% range, n)         | v2 (95% range, n)         | Right only with v1 | Right only with v2 | Exact McNemar p |
| --------------- | ------------------------- | ------------------------- | ------------------ | ------------------ | --------------- |
| Category        | 87.3% (81.1–91.7%, n=150) | 94.0% (89.0–96.8%, n=150) | 4                  | 14                 | 0.031           |
| Priority, exact | 73.3% (65.7–79.8%, n=150) | 91.3% (85.7–94.9%, n=150) | 5                  | 32                 | < 0.001         |

Decision rule (fixed before any data): adopt v2 only if a metric is higher with p < 0.025 and neither is lower with p < 0.025.

**Adopt v2**: better on at least one metric and worse on neither, at p < 0.025.

## Auto-apply threshold, checked again with v2

The app applies a triage suggestion automatically only when the model's confidence is at least
0.95 (changed from 0.7 in commit `e624a74`). Below it, a person decides. The same check run on
v2's answers:

| Auto-apply at | v1: sent to a person | v1: wrong categories caught | v1: auto-applied category / priority right | v2: sent to a person | v2: wrong categories caught | v2: auto-applied category / priority right |
| ------------- | -------------------- | --------------------------- | ------------------------------------------ | -------------------- | --------------------------- | ------------------------------------------ |
| 0.7           | 1 (1%)               | 0 of 19                     | 87.2% / 73.2%                              | 2 (1%)               | 1 of 9                      | 94.6% / 91.2%                              |
| 0.9           | 6 (4%)               | 4 of 19                     | 89.6% / 72.2%                              | 3 (2%)               | 1 of 9                      | 94.6% / 91.8%                              |
| **0.95**      | 33 (22%)             | 13 of 19                    | 94.9% / 74.4%                              | **23 (15%)**         | **4 of 9**                  | **96.1% / 92.9%**                          |
| 1.0           | 96 (64%)             | 15 of 19                    | 92.6% / 79.6%                              | 58 (39%)             | 7 of 9                      | 97.8% / 92.4%                              |

v2's confidences: 1.0 on 92 tickets, 0.95 on 35, 0.9 on 20, 0.8 on 1, 0.5 on 2. **The threshold
stays at 0.95:** with v2 it sends fewer tickets to a person (15% instead of 22%), and what it
applies automatically is right more often. 1.0 would catch more wrong categories but would send
39% of tickets to a person.

## Limitations

- **Same source for rules and labels.** v2's rules were written from the same rubric that was used
  to label the test tickets. Some of the gain may be the prompt learning the labeller's
  conventions rather than understanding support tickets better. The labels themselves were not
  changed after v1 was measured.
- **In-sample threshold.** The 0.95 threshold was chosen and rechecked on these same 150 tickets.
  There is no separate held-out set, so real-world numbers may be lower.
- **Category is not proven better on its own.** 14 tickets improved and 4 got worse (p = 0.031),
  which does not pass the 0.025 bar. The adoption rests on priority.
- **One model, one run each.** Results are for `gemini-3.5-flash-lite` only, with one run per
  prompt. Another model may behave differently.
- **Synthetic tickets.** The dataset is written for this project, not taken from real customers.
- The v2 run measured triage only (status "stopped" after its 150 triage tickets). Retrieval,
  drafts and injection results come from the v1 baseline run, which they do not depend on.
